# Hosted engine recommendation for PoseForge

## Approval shortlist

### 1. Together AI — approve as the primary multi-model provider

Use one `TOGETHER_API_KEY` and the OpenAI-like Images API for:

- **FLUX.2 Pro** — default transformation engine; multi-reference, good identity consistency, structured prompting; $0.03/image.
- **FLUX.2 Max** — premium/final engine for difficult identity and multi-reference edits; $0.070/MP.
- **FLUX.2 Dev** — economical advanced engine; $0.0154/image, but downloadable weights are non-commercial unless separately licensed.
- **FLUX.2 Flex** — typography and parameter-control specialist; $0.03/image.
- **Ideogram 4** — design/text specialist; $0.06/image.
- Optionally expose Qwen Image 2 and the catalog's Google/OpenAI image models later through the same adapter.

Why first: this is the broadest verified current catalog behind one token and one image endpoint. It directly supports multiple reference images, which maps naturally to PoseForge character + pose + style inputs.

### 2. Replicate — approve as the secondary/experimental provider

Use `REPLICATE_API_TOKEN` for:

- FLUX.2 Pro/Max parity and fallback.
- FLUX.2 klein 9B for low-cost experiments.
- PuLID-FLUX, InstantID, PhotoMaker, and custom Cog models for expert mode.
- Webhook/async predictions and custom deployments.

Why second: best long-tail catalog and easiest route to custom pose/identity pipelines. Do not label InstantID commercial-safe without resolving the InsightFace dependency license.

### 3. RunPod Serverless — approve only as an Advanced/self-host phase

Use `RUNPOD_API_KEY` for a containerized workflow combining explicit pose conditioning (OpenPose/ControlNet) with an identity mechanism and a commercially permitted base model. Configure six max workers for PoseForge bulk generation.

Why later: it provides the strongest deterministic pose-control path, but requires packaging, weights, model caching, cold-start tuning, and licensing work.

### Do not prioritize

- **Hugging Face Inference Providers:** valuable for evaluation and one-token routing, but the common image-to-image schema omits advanced model-specific controls. Use it as an optional abstraction, not the initial production integration.
- **fal.ai:** likely a strong low-latency alternative and is verified live for current FLUX.2 Dev/Klein through Hugging Face's official provider mappings. However, fal.ai's own pricing and queue pages were blocked by its browser checkpoint during this review, so no unverified price claim should drive approval.
- **Older SDXL identity adapters as the default:** InstantID, PuLID, and PhotoMaker remain useful expert tools, but current FLUX.2 multi-reference models are better first-line hosted choices. Keep explicit pose ControlNet as a separate advanced pipeline because semantic multi-reference editing does not guarantee keypoint-perfect anatomy.

## Adversarial review and unknowns

1. A six-image benchmark must compare identity similarity, pose similarity, hands/anatomy, latency, and failure rate before making FLUX.2 Pro the UI default.
2. Together's serverless limits are dynamic; there is no fixed published concurrency guarantee. Implement 429/503 backoff and per-provider queue caps.
3. Replicate FLUX.2 editing cost depends on run fee plus input and output megapixels. Cost estimates must use actual dimensions, not a flat token count.
4. Hosted API commercial-use terms, output ownership, data retention, and regional processing still need a legal/terms pass. Weight licenses alone do not answer those questions.
5. FLUX Dev/Klein downloadable weights are non-commercial. Self-hosting them commercially requires a separate license; hosted endpoint use must follow the provider/model terms.
6. Exact pose transfer may still require OpenPose/ControlNet or a bespoke pipeline. Multi-reference identity consistency is not a substitute for skeletal conditioning.

## Recommended architecture

Implement a provider-neutral capability layer rather than a flat model dropdown:

- capabilities: `textToImage`, `singleImageEdit`, `multiReference`, `poseControl`, `identityReference`, `batch`, `async`
- cost formula per model: flat image, megapixel, or GPU-second
- provider adapters: Together first, Replicate second, RunPod advanced
- store provider/model/version, estimated cost, actual billed units when available, and input/output dimensions for every generation
